Same Entity?

When two reports name an organization differently, is there enough evidence to link them, keep them separate, or send them for human review?

Synthetic data · fictional organizations

Hi, I'm Mahek Sota.

I'm a software engineer at the University of Mississippi and a USC MS Computer Science graduate. I built Same Entity? as an independent project to study one question in organization matching across languages.

Why I built this

I wanted to explore what makes an automated match trustworthy when reports use different names, omit details, or disagree. Name similarity is easy to compute and easy to over-trust. In this fixture, “Fundación Agua Clara” and “Fundación Aguas Claras” normalize to the same words and are both in Lima, yet they are different organizations. I wanted a small system where every decision points to the exact words it relied on, and where Needs review is a legitimate answer rather than a failure.

Why I'd be a good candidate

This project builds on the kind of work I already do:

  • Extraction from messy documents. I've built Python pipelines that extract and classify references from research PDFs. The extractor here applies the same habits: explicit patterns, exact source excerpts, and recorded failures instead of silent guesses.
  • Human review that gets faster without losing accuracy. I developed an LLM-assisted workflow that reduced manual citation review from about 30 minutes to about two. This project follows the same principle: automate the first pass and show the reviewer exactly which text each decision relied on.
  • Pipelines at scale. I've operated Python, Kafka, and PostgreSQL pipelines that processed 50M+ records, so I design for reruns, reproducible outputs, and data that drifts from what the rules expected.

What I'd bring to a team

  • Working through ambiguous inputs. I start by writing down what the inputs actually look like, decide what counts as evidence, and keep unknown values unknown instead of filling them in.
  • Validating outputs. I hold data out before tuning, report errors with numerators and denominators, and publish results that don't flatter the approach. Here, the evidence-aware matcher did not beat the baseline on the held-out set, and the report says so.
  • Making disagreements visible. When sources conflict, reviewers should see the conflicting excerpts side by side, not a single score.
  • Operating pipelines after launch. I rely on deterministic reruns, focused tests for the cases that matter, and outputs that can be audited later.

Keeping claims separate. The accomplishments above come from my professional work. Every number in the Demo and Detailed Report tabs was measured only on this prototype's 73-pair synthetic fixture. This project is not evidence of production multilingual experience.
